# Stunt Car Racer (C64) — RAM & Cycle Optimization Loop

Modeled on [Dornbi/plane-pilot `docs/ram-loop.md`](https://github.com/Dornbi/plane-pilot/blob/main/docs/ram-loop.md).

`tools/opt_loop.sh` runs an unattended optimization loop that frees RAM and cuts frame cycles on a stock PAL C64 (`x64sc -pal`). **RAM and cycles matter equally**: freeing contiguous RAM (e.g. by compacting cold menu/UI/setup code) unlocks speed tables and unrolling, while cutting cycles in `race_main_loop` directly increases frame rate.

This file is the loop's memory. Every pass reads it first.

## Goal & Metrics

- **RAM (`make fram`)**: `"Free, allocatable"` from `tools/analyze_ram.py` (baseline: **202 B** free, largest run 104 B at `$BF42`, plus 17 statically unreferenced ZP bytes). Shrinking code in `mod_0800_3fff`, `mod_8000_a3ff`, `mod_c000_cfff`, or `mod_e000_ffff` automatically lowers `mod_*_end` and grows `"Free, allocatable"`.
- **Cycles (`make bench`)**: CIA2 chained 32-bit cycle counter (`$DD04–$DD07`, unused by the game) timing the full `race_main_loop` race loop across 7 deterministic PAL driving scenes (total baseline: **1,546,541** cycles/frame across 7 scenes, avg ~220,934 cyc/f ≈ **4.46 FPS**).
- **Acceptance gates**: `Free, allocatable` must not drop; every scene must stay within `+2%` of `cycles-baseline`; and the change must either free RAM or cut `TOTAL` cycles by at least `0.5%` vs the last kept state.

The script parses this line verbatim — keep its exact format:

cycles-baseline: 02_little_grid=206799 03_little_boost=205914 04_stepping_jump=215297 05_hump_weave=241543 06_high_jump=208131 07_roller_bank=238156 08_drawbridge_wall=230701 09_high_jump_air=172360 10_opp_race=197002

## Rules (Binding for Worker & Reviewer)

1. **Pixel-identical rendering & byte-identical physics**: `make shots` must report `0` differing pixels across all 10 scenes (including airborne wheel struts & live opponent car) and `0` differing bytes in physics state RAM (`$0100–$015F`) vs `tests/golden/`.
2. **Bit-exact 6510 unit tests**: `make target-test` must pass all 19 suites (686 cases) with `0` failures and all 19 per-suite 32-bit digests matching `orig/scracer_unpacked_64k.bin` (`0xffa9e2b4`).
3. **Static safety checks**: `make check` (`check_memory_map.py` + `check_safety.py`) must pass; `$D000–$DFFF` stays zeroed at boot; VIC Bank 1 (`$4000–$7FFF`) buffers stay intact; IRQ/NMI register preservation stays intact.
4. **Standalone PRG builds cleanly**: `make prg` must recompute the `$42C5/$42C6` boot checksum automatically and pack cleanly below `$D000` with verified zero-overlap forward RLE depacking.
5. **Keep every feature**: Nothing may be dropped (single player, multiplayer, league progression, disk save/load, sound/SFX, all 8 tracks, menus).
6. **One small, reviewable idea per pass**: Never touch `tests/golden/`, `tests/harness.asm`, or this ledger directly during a worker pass.

## Architecture Notes & RAM Reclamation Opportunities

- **Boot anti-tamper checksum (`boot_verify_checksum`)**: Sums 7 RAM ranges (`$0840..$42C5`, `$4F00..$5700`, `$5780..$8000`, `$80C0..$A200`, `$A380..$C000`, `$C780..$D000`, `$E000..$FFE2`) against `$42C5/$42C6`. `make bin` runs `tools/fix_checksum.py` automatically so modified builds pass cleanly.
- **Stack page `$0100–$01FF`**: `$0100–$01C1` holds game state; `$01C2–$01FF` (62 B) is the hardware stack.
- **Pages `$0200–$07FF`**: 3D polygon/span/vertex buffers (`$0200–$03FF`, `$0400–$07FF`).
- **VIC Bank 1 (`$4000–$7FFF`)**: Double-buffered bitmaps (`$4000–$5BFF`, `$6000–$7BFF`), shared Screen RAM (`$5C00–$5FE7`), sprite pointers (`$5FF8–$5FFF`). Boot init (`$3FFB–$42C6`) runs once and is overwritten by Bitmap 0.
- **Under-I/O RAM (`$D000–$DFFF`)**: Populated at boot (`$41E2`) with menu/cockpit backup via `$01=$34` (`3,541/4,096` B used at runtime).
- **Verified Free Pockets (202 B baseline)**: `$BF42–$BFA9` (104 B), `$7FC6–$7FFF` (58 B), `$FFE2–$FFF9` (24 B), `$5FE8–$5FF7` (16 B).
- **Unreferenced Zero-Page slots (17 B)**: `$26 $42 $47 $65 $67 $84 $85 $87 $88 $96 $AE $BB $E2 $E5 $E6 $F3 $FF` (verify dynamically before claiming).
- **Prime RAM reclamation targets**:
  - Cold UI/menu/division/disk routines in `mod_0800_3fff.asm` (14 KB) and `mod_8000_a3ff.asm` (9 KB) — shrinking code immediately grows `mod_*_end` free space!
  - Unreachable 7-byte block before `vid_select_bitmap0` (`$3F84–$3F8A`), unused `$8C70–$8C87` / `$8C93–$8CAB` / `$8CB7–$8CCF` zero pads, and redundant sequences in hot/cold code.
- **Prime Cycle targets**:
  - `render_track_frame` (189,918 cyc/f = 78.6%): 3D projection, bitmap clear, SMC line/polygon rasterizers (`$2458–$27C5`, `$F8CA–$FCBF`).
  - `math_mul_u8_u8` (shift-and-add 8×8→16 multiply, ~140 cyc/call — massive speedup once RAM is freed for quarter-square tables!).
  - `math_ashift_s24` (24-bit signed shift, 29 call sites — currently uses 6-cycle absolute `lsr var_ashift_s24_tmp` in inner loop; can shrink AND speed up simultaneously!).
  - `math_abs_s16` (16-bit abs, 32 call sites).

## Dead Ends

- **NEVER delete or shorten the 4 × 14-byte `*_band_clip` blocks** (`steep_l_band_clip`, `steep_r_band_clip`, `shall_l_band_clip`, `shall_r_band_clip`) immediately before `*_no_step_*` in `src/mod_e000_ffff.asm`: they are reached via runtime SMC (`bcs $e2` patched by `render_enable_line_band_clip`) whenever the opponent car is viewed at an inverted/flipped angle (`flg_opp_render_flags` bit 7 set). Deleting them causes an infinite loop during opponent collisions/flips, and changing their `-30` (`$e2`) offset breaks `16_smc_horiz`. Protected by compile-time `.cerror` guards in `render_enable_line_band_clip`.
